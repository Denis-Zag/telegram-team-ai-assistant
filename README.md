# Telegram Team AI Assistant

Telegram-бот для командных обсуждений. Он записывает новые сообщения
группы, обрабатывает PDF/DOCX через Docling, отвечает по общему контексту чата
и документов, а после остановки готовит структурированный итог разговора.

Проект запускается локально без Docker. Архитектура включает постоянное
хранилище сессий, семантический поиск, обработку документов и несколько
независимых AI-пайплайнов.

## Что получается в итоге

1. В группе вызывают `/start_listening`.
2. Бот молча сохраняет новые текстовые сообщения участников.
3. Во время обсуждения можно написать `/ask вопрос`, упомянуть бота через
   `@username` или спросить «Что думаешь?».
4. Во время активной записи можно отправить PDF или DOCX: бот извлечёт текст,
   страницы, сохранит фрагменты и вернёт краткое резюме.
5. По `/stop_listening` запись прекращается, а бот выдаёт тему, позиции,
   решения, открытые вопросы и следующие действия.
6. `/reset` удаляет сообщения и документы только той группы, где вызвана
   команда.

## Почему нужны два хранилища

- **SQLite** хранит точную хронологию сообщений. Она нужна для итогового резюме,
  где важны порядок реплик и авторы.
- **Pinecone** хранит embeddings тех же сообщений. Он нужен, чтобы находить по
  смыслу только релевантные фрагменты для конкретного вопроса.

Данные разных Telegram-групп и разных сессий разделены фильтрами `chat_id` и
`session_id`.

## Пайплайны Haystack

Три основных пайплайна проекта:

1. Индексация: сообщение или Docling-чанки → OpenAI-совместимый embedding через
   ProxyAPI → Pinecone.
2. Вопрос: embedding вопроса → поиск Pinecone → prompt → ответ AI.
3. Итог: полная упорядоченная переписка из SQLite → prompt → резюме AI.

Дополнительный четвёртый пайплайн формирует краткое первичное резюме
загруженного документа. PDF с текстовым слоем разбирается быстрым model-free
режимом `NativePdfPipeline`; соседние элементы одной страницы объединяются,
чтобы не создавать десятки лишних embeddings.

Файл `34_Extractive_QA_Pipeline.ipynb` сохранён как справочный пример
extractive QA в Haystack. Рабочий Telegram-бот использует генеративный RAG,
поскольку отвечает по общей переписке и нескольким документам.

## Privacy Mode для работы в группе

По умолчанию Telegram включает Privacy Mode для групповых ботов. В таком
режиме бот получает команды, адресованные ему, сообщения через него и ответы
на его реплики, но не получает обычный разговор участников. Поэтому команды
будут работать, а требование «слушать переписку команды» — нет.

Настройка через Telegram:

1. Откройте официальный чат `@BotFather`.
2. Отправьте `/mybots` и выберите своего бота.
3. Откройте **Bot Settings → Group Privacy**.
4. Нажмите **Turn off** (или используйте `/setprivacy`, выберите бота и
   **Disable**).
5. Если бот уже был в тестовой группе, удалите его из группы и добавьте заново:
   Telegram указывает, что это требуется для применения изменения.

Альтернатива — сделать бота администратором группы: администраторы также
получают все сообщения. Для локального проекта безопаснее дать минимум прав и
отключить Group Privacy, а не выдавать лишние административные возможности.

Важно: бот увидит только **новые** сообщения после добавления и запуска. Старую
историю Telegram ему не передаёт. Сообщения других ботов обычный групповой бот
тоже не получает.

Официальное описание: [Telegram Bot Features — Privacy Mode](https://core.telegram.org/bots/features#privacy-mode)
и [Telegram Bots FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

## Тестовая Telegram-группа

Это обычная приватная Telegram-группа, созданная только для проверки проекта.
Она не создаётся программой и не требует отдельного сервиса.

Минимальный состав:

- ваш основной Telegram-аккаунт;
- второй ваш аккаунт или знакомый участник, чтобы были реплики разных людей;
- созданный через BotFather бот.

Порядок создания: **Telegram → Новая группа → добавить участника → назвать,
например, «Тест Team AI Assistant» → добавить бота**. Если Telegram не даёт
создать группу только с собой, временно понадобится второй участник. Рабочую
или семейную группу лучше не использовать: сообщения уходят во внешние сервисы
ProxyAPI и Pinecone.

## Подготовка на Windows

Требуется Python 3.12.

```powershell
cd D:\VibeProjects\Educational_projects\telegram-team-ai-assistant
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env` локально:

- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `PROXYAPI_KEY` — ключ ProxyAPI. Отдельный ключ OpenAI не нужен: Haystack
  передаёт этот ключ в OpenAI-совместимый API ProxyAPI;
- `PINECONE_API_KEY` — ключ Pinecone;
- при необходимости имя существующего Pinecone-индекса и регион.

`MAX_DOCUMENT_BYTES` задаёт максимальный размер PDF/DOCX. По умолчанию это
10 000 000 байт, то есть примерно 10 МБ.

Не присылайте ключи в чат. `.env`, SQLite-база, логи и виртуальное окружение
исключены из Git.

## Проверки и запуск

Сначала офлайн-тесты, которые не тратят API-запросы:

```powershell
python -m unittest discover -s tests -v
```

Затем единичная живая проверка интеграций:

```powershell
python preflight.py
```

`preflight.py` не запускает Telegram polling. Он проверяет токен Telegram,
выполняет реальный embedding, запись/поиск/удаление в Pinecone и запрос к
чат-модели. Вывод не содержит ключей и подходит как обезличенное доказательство
для отчёта о тестировании. Живая проверка расходует небольшой объём API.

Документный контур проверяется отдельно на приложенном тестовом PDF:

```powershell
python document_preflight.py
```

Скрипт локально разбирает `samples/Auto_Service_AI_Triage_Overview.pdf`,
временно записывает его чанки в Pinecone, получает резюме и контрольный
RAG-ответ, а затем удаляет тестовые чанки. Telegram polling не запускается.

После успешного preflight:

```powershell
python bot.py
```

Остановка: `Ctrl+C` в том же окне.

## Команды

- `/start` и `/help` — краткая инструкция;
- `/start_listening` — начать новую сессию;
- `/stop_listening` — остановить её и получить итог;
- `/ask <вопрос>` — спросить по активной или последней сессии;
- `/status` — состояние, число сообщений и документов;
- `/reset` — очистить сообщения и документы текущей группы в SQLite и Pinecone.

PDF/DOCX отправляется обычным вложением во время активной записи. После
обработки `/ask` ищет одновременно в репликах участников и фрагментах файла.

## Ограничения текущей версии

- Поддерживаются текстовые сообщения, PDF и DOCX; голосовые сообщения не
  обрабатываются.
- Model-free обработка PDF требует текстового слоя. Скан без распознанного текста
  нужно предварительно пропустить через OCR.
- В итог попадает не более `MAX_SUMMARY_MESSAGES` последних сообщений сессии.
- Бот работает только пока запущен `bot.py` на компьютере.
- Удаление сообщения внутри Telegram само по себе не удаляет уже сохранённую
  копию; для тестовой группы используйте `/reset`.
- Ответ модели подтверждает форму работы пайплайна, но содержательную точность
  нужно проверить вручную по исходному диалогу.
