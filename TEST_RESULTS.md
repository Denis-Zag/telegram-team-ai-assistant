# Проверка Telegram Team AI Assistant

## Текущее состояние

На 9 октября 2026 года проверены конфигурация, SQLite, структура пайплайнов,
обработка PDF через Docling, живые обращения к Telegram, ProxyAPI и Pinecone,
а также интерактивная работа в тестовой Telegram-группе. Основные функции
подтверждены фактическими прогонами.

## Основной live preflight

Команда:

```powershell
python preflight.py
```

Фактический результат:

```text
[OK] Telegram Bot API: токен принят, бот найден
Upserting: 100%|████████████████████████████████████████| 1/1
[OK] ProxyAPI Embeddings + Pinecone: документ записан
[OK] Pinecone retrieval + ProxyAPI Chat: ответ получен
[OK] Пайплайн итогов: ответ получен
[OK] Очистка: тестовый документ удалён
```

Вывод: токен Telegram принят, embedding и чат-запрос ProxyAPI работают,
Pinecone записывает и возвращает контекст, пайплайн итогов отвечает, временный
документ удаляется.

Фактический результат:

- проверены изоляция групп и сессий, порядок сообщений, защита от дублей,

## Проверка документа

Тестовый файл: `samples/Auto_Service_AI_Triage_Overview.pdf`.

Сначала я проверил файл локально. Он содержит три читаемые страницы без
наложений и обрезанного текста. Model-free режим Docling извлёк страницы 1–3,
создал три итоговых чанка и нашёл контрольные поля `client_id` и `thread_id`.

Команда живой проверки:

```powershell
python document_preflight.py
```

Фактический результат после исправления лимита ответа и нормализации SHA-256:

```text
[OK] Docling: документ разобран, фрагментов=3, страниц=1,2,3
[OK] ProxyAPI Embeddings + Pinecone: записано фрагментов=3
[OK] ProxyAPI: краткое резюме документа получено
[OK] Pinecone retrieval + ProxyAPI Chat: факты подтверждены
[OK] Очистка: тестовые чанки документа удалены
```

Промежуточные прогоны также были полезны: первый выявил слишком маленький лимит
ответа для `gpt-5-mini`, второй — слишком буквальную проверку написания
`SHA-256`. После исправлений полная проверка прошла. Каждый прогон завершился
удалением временных чанков.

## Найденные и исправленные проблемы

В ходе живой проверки были обнаружены и устранены четыре проблемы:

1. Первичное резюме документа обрывалось при лимите 600 токенов. Лимит
   документного пайплайна увеличен до 1 500 токенов; повторная проверка прошла.
2. Проверка строки `SHA-256` была слишком чувствительна к оформлению ответа
   модели. Сравнение нормализовано с учётом пунктуации; контрольный факт
   подтверждён.
3. Сложный запрос `/ask` завершался без видимого текста: ProxyAPI возвращал
   `200 OK`, но модель расходовала лимит 1 200 токенов на рассуждение. Лимит
   пайплайна вопросов увеличен до 3 000 токенов. Тот же запрос по переписке и
   PDF после исправления успешно вернул содержательный ответ.
4. При `/stop_listening` аналогично не формировался итог при лимите 900
   токенов. Лимит итогового пайплайна увеличен до 3 000 токенов. Повторная
   генерация по сохранённой переписке и новый прогон в Telegram завершились
   успешно.

После исправлений повторно выполнены синтаксическая проверка и 19 модульных
тестов — все проверки пройдены.

## Фактическая проверка `/stop_listening`

9 октября 2026 года после исправления лимита генерации итогов выполнен повторный
прогон с репликами двух участников. Бот подтвердил остановку записи, а затем
сформировал итог с ключевыми пунктами:

```text
Тема
- Хранение истории обращений (памяти) для бота — как избежать смешивания данных между клиентами и потоками.

Основные позиции
- @denis_zagrebnev: предлагает хранить раздельную память по сочетанию client_id и thread_id, чтобы обращения разных клиентов не смешивались.
- Лидия: согласна с раздельной памятью; проверит изоляцию двух клиентов, но отмечает риск — при повторном использовании одного thread_id история может попасть не в тот диалог.

Принятое решение
- Оставляем раздельную память (по сочетанию client_id и thread_id). Решение подтверждено @denis_zagrebnev.

Нерешённые вопросы
- Срок хранения истории обращений — не определён.

Следующие действия
- Лидия: до завтра проверит обязательные поля заявки и подготовит список найденных рисков, включая риск повторного использования thread_id.
```

Вывод: итог корректно выделил тему, позиции обоих участников, принятое решение,
риск, нерешённый вопрос и следующее действие. Проверка пройдена.
